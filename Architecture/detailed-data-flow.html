🔍 Multi-Drone System - Detailed Data Flow

Exact Data Structures: Redis → PostgreSQL → Elasticsearch

🎯 SCENARIO 1: User Clicks Map → Drone Flies
1 Backend Checks Redis Cache ~3ms
📋 Redis Command:
GET drone:drone-1:state
💾 What's Stored in Redis:
Key: "drone:drone-1:state" Type: String (JSON) TTL: 5 seconds Value: { "droneId": "drone-1", "position": { "x": 0, "y": 0, "z": 50 }, "battery": 85.5, "status": "flying", "isArmed": true, "lastUpdated": "2026-01-31T14:30:45Z" }
🔑 Redis Keys Used:
• drone:{id}:state - Current drone state (TTL: 5s)
• drone:{id}:alerts:count - Active alerts counter (TTL: 60s)
• drone:{id}:telemetry - List of last 100 telemetry points (TTL: 300s)
2 Backend Processes Flight Command ~10ms
⚙️ C# Code:
var result = await droneService.GoToAsync( droneId: "drone-1", targetX: 150.5, targetY: 220.8, targetZ: 50, speed: 15, mode: FlightMode.Safe );

4 Update Redis Cache ~2ms
📋 Redis Commands:
// Update state with new TTL SETEX drone:drone-1:state 5 { "droneId": "drone-1", "position": {"x": 0, "y": 0, "z": 50}, "targetPosition": {"x": 150.5, "y": 220.8, "z": 50}, "battery": 85.5, "status": "flying", "isArmed": true } // Add to recent commands list (keep last 100) LPUSH drone:drone-1:commands {"type": "goto", "target": [150.5, 220.8, 50]} LTRIM drone:drone-1:commands 0 99
5 Index Event in Elasticsearch ~50ms (async)

Document Indexed:
POST /drone-events-2026.01/_doc { "eventId": "a3f2e8d9-4c5b-...", "droneId": "drone-1", "eventType": "FlightCommandReceived", "severity": "Info", "message": "Drone moving to (150.5, 220.8, 50)", "timestamp": "2026-01-31T14:30:45.123Z", "metadata": { "targetPosition": {"x": 150.5, "y": 220.8, "z": 50}, "mode": "Safe", "speed": 15 } }
🔄 Sync Strategy:
Option A: Immediate (used here):
Backend indexes to ES immediately after saving to PostgreSQL

Option B: Bulk Async:
Background job reads from PostgreSQL every 10s and bulk indexes to ES

Option C: CDC (Change Data Capture):
Debezium listens to PostgreSQL WAL logs and auto-syncs to ES

4 Increment Redis Alert Counter ~1ms
📋 Redis Commands:
// Increment active alerts count INCR drone:drone-1:alerts:count // Result: 3 (if was 2 before) // Set TTL if key is new EXPIRE drone:drone-1:alerts:count 60 // Add to recent alerts list (sorted set by timestamp) ZADD drone:drone-1:alerts:recent 1738337712 "b7d3f9a2-6e8c-..." // Score is Unix timestamp, value is alert ID // Keep only last 50 alerts ZREMRANGEBYRANK drone:drone-1:alerts:recent 0 -51
🔑 Redis Keys for Alerts:
• drone:{id}:alerts:count - Integer counter (INCR/DECR)
• drone:{id}:alerts:recent - Sorted Set (timestamp → alertId)
• alerts:critical - Global list of critical alerts (all drones)
5 Index Alert in Elasticsearch ~30ms
🔍 Document Indexed:
POST /drone-events-2026.01/_doc { "eventId": "b7d3f9a2-6e8c-...", "droneId": "drone-1", "eventType": "WeatherWarning", "severity": "Warning", "message": "Moderate rain detected in flight area", "timestamp": "2026-01-31T14:35:12.456Z", "metadata": { "weather": { "condition": "Rain", "description": "moderate rain", "temperature": 15.5, "humidity": 85, "windSpeed": 7.5 }, "dronePosition": { "lat": 32.766, "lng": 35.038, "altitude": 50 } } } // Elasticsearch automatically creates inverted index on "message" field // This enables fast full-text search like: "rain" or "moderate rain"

🔍 SCENARIO 3: User Searches "engine failure"
1 Query Elasticsearch ~25ms
🔍 Elasticsearch Query DSL:
POST /drone-events-2026.01/_search { "query": { "bool": { "must": [ { "match": { "message": { "query": "engine failure", "operator": "and" } } } ], "filter": [ { "range": { "timestamp": { "gte": "now-24h" } } }, { "term": { "isAcknowledged": false } } ] } }, "sort": [ {"timestamp": {"order": "desc"}} ], "size": 50 }
💡 Why This is Fast:
• Inverted Index: ES pre-indexes "engine" and "failure" separately
• Term Dictionary: Binary search on sorted terms
• Posting List: Quick lookup of documents containing terms
• SQL Equivalent: Would be LIKE '%engine%' AND message LIKE '%failure%' = SLOW!
2 Optional: Get Statistics +10ms
📊 Aggregation Query:
POST /drone-events-2026.01/_search { "size": 0, "query": { "match": {"message": "engine failure"} }, "aggs": { "by_drone": { "terms": { "field": "droneId", "size": 10 } }, "by_severity": { "terms": { "field": "severity" } }, "over_time": { "date_histogram": { "field": "timestamp", "calendar_interval": "1h" } } } } // Returns: // - Count per drone // - Count per severity // - Timeline of failures by hour

📊 SCENARIO 4: Simulation Tick → Store Telemetry
1 Simulation Tick (every 100ms) ~5ms
⚙️ C# Code:
var telemetry = new DroneTelemetry { DroneId = "drone-1", Timestamp = DateTime.UtcNow, Latitude = 32.766, Longitude = 35.038, Altitude = 52.3, Speed = 14.8, Heading = 87.5, BatteryPercent = 85.2, SignalStrength = -45 };
2 Store Recent in Redis ~2ms
📋 Redis Commands:
// Add to list (keep last 100 points = 10 seconds at 100ms tick) LPUSH drone:drone-1:telemetry { "t": 1738337712456, "lat": 32.766, "lng": 35.038, "alt": 52.3, "spd": 14.8, "bat": 85.2 } // Trim to keep only last 100 LTRIM drone:drone-1:telemetry 0 99 // Set expiry (5 minutes if no updates) EXPIRE drone:drone-1:telemetry 300
💡 Why Not Every Point to DB?
• 10 drones × 10 ticks/sec = 100 INSERTs/sec
• Over 1 day = 8.6 million records!
• Redis keeps "recent" (last 10 seconds) for real-time display
• PostgreSQL stores 1 point per second (downsampled)

💡 Why Elasticsearch for Telemetry?
Use Cases:
• "Show me all flights where battery dropped below 20%"
• "Aggregated battery drain over last 30 days"
• "Correlation: altitude vs battery drain rate"
• "Geo queries: all telemetry within 5km radius"

SQL would require:
Complex JOINs, slow WHERE clauses, manual aggregations

✅ Summary: What Goes Where

⚡ Redis

Drone State (5s TTL):
drone:{id}:state

Alert Counter (60s):
drone:{id}:alerts:count

Recent Alerts (Sorted Set):
drone:{id}:alerts:recent

Telemetry (Last 100):
drone:{id}:telemetry

Commands History:
drone:{id}:commands

💾 PostgreSQL

Drones (Master Data):
• All drone info
• Current status

DroneEvents (All):
• Every alert/event
• Permanent storage

DroneTelemetry:
• 1 point/second
• Historical data
• Partitioned by month

Missions:
• Flight plans
• Waypoints

🔍 Elasticsearch

drone-events-YYYY.MM:
• Full-text searchable
• All events
• Monthly indices

drone-telemetry-YYYY.MM:
• Analytics queries
• Aggregations
• Geo queries

Use For:
• "engine failure"
• Battery patterns
• Correlations
