💡 Scenario 1: Click to Fly
Flow:
1. User clicks map
2. Frontend → API Gateway
3. Backend checks Redis cache
4. Backend saves to PostgreSQL
5. Backend indexes in Elasticsearch
6. SignalR broadcasts update
7. Frontend shows drone moving
⚠️ Scenario 2: Weather Alert
Flow:
1. Timer tick (100ms)
2. Backend → Weather API
3. Rain detected!
4. Alert created → PostgreSQL
5. Alert indexed → Elasticsearch
6. SignalR broadcast
7. Toast notification on UI
🔍 Scenario 3: Search Alerts
Flow:
1. User searches "engine failure"
2. Frontend → API Gateway
3. Backend → Elasticsearch
4. Full-text search (< 50ms)
5. Results aggregated
6. Response to Frontend
7. Display filtered alerts
⚡ Scenario 4: Get Drone State
Flow (with Redis):
1. Frontend requests state
2. Backend checks Redis
3a. Cache HIT: Return (3ms) ✅
3b. Cache MISS: Query DB
4. Store in Redis (TTL: 5s)
5. Return to Frontend
Result: 10x faster!
📊 Scenario 5: Analytics Query
Flow:
1. Dashboard loads
2. Backend → Elasticsearch
3. Aggregation query:
  • Battery drain patterns
  • Flight time distribution
  • Alert frequency by type
4. Results in < 100ms
5. Render charts

🎓 Architecture Highlights

⚡ Redis Cache Layer

Purpose: Reduce database load by 80%
Use: Drone states, active alerts, sessions
Speed: 1-3ms vs 10-30ms (DB)
TTL: 5 seconds for drone state

🔍 Elasticsearch Layer

Purpose: Fast search & analytics
Use: Full-text alert search, aggregations
Speed: < 50ms for complex queries
Scale: Handles millions of records

📡 SignalR Real-time

Purpose: Live updates without polling
Use: Drone position, alerts, telemetry
Frequency: 10 updates/second
Connections: Scales to 1000s of clients
