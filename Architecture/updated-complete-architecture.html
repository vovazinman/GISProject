🎯 SCENARIO 1: Click to Fly
1User clicks map → lat/lng
2Frontend → API: POST /goto
3Backend → Redis: GET state
4PostgreSQL: INSERT event
5Redis: UPDATE state (TTL 5s)
6ES: Index document
7SignalR: Broadcast update
8Frontend: Move drone on map
Redis: drone:drone-1:state PostgreSQL: DroneEvents table ES: drone-events-2026.01 index
⚠️ SCENARIO 2: Weather Alert
1Timer tick (30s interval)
2Backend → Weather API call
3Rain detected! Create alert
4PostgreSQL: INSERT alert
5Redis: INCR alerts:count
6ES: Index with weather data
7SignalR: Push to clients
8Frontend: Toast notification
Redis: INCR drone:1:alerts:count ES: Full-text searchable message
🔍 SCENARIO 3: Search "engine failure"
1User types search query
2Frontend → API: GET /search
3Backend → Elasticsearch query
4ES: Full-text match on message
5ES: Filter by timestamp, severity
6ES: Aggregate by drone
7Return results (< 50ms)
8Frontend: Display results
ES Query: match on "message" field Result: Inverted index lookup
📊 SCENARIO 4: Telemetry Stream
1Simulation tick (100ms)
2Update drone position/battery
3Redis: LPUSH telemetry (last 100)
4PostgreSQL: INSERT (1/second)
5ES: Bulk index (every 10s)
6SignalR: Stream to clients
7Frontend: Update charts
8Smooth animation
Redis: Recent (10s window) DB: Historical (long-term)
🔋 SCENARIO 5: Low Battery Alert
1Simulation: Battery drops to 19%
2Alert Manager: battery < 20%
3Create CRITICAL alert
4PostgreSQL: INSERT critical event
5Redis: DEL state (invalidate cache)
6Redis: INCR alerts:count
7SignalR: Broadcast critical alert
8Frontend: Red banner + sound
Cache Invalidation Pattern Ensure fresh data on critical events
📈 SCENARIO 6: Analytics Dashboard
1User opens analytics page
2Frontend → API: GET /analytics
3Backend → ES aggregation
4Query: Battery drain over time
5ES: DateHistogram (1M records)
6ES: Bucketed by hour
7Return in 300ms
8Chart.js renders graph
Why ES: SQL GROUP BY = 30+ seconds ES Aggregation = 300ms

✅ Data Storage Summary

⚡ Redis Cache

Keys Pattern:
drone:{id}:state
drone:{id}:alerts:count
drone:{id}:alerts:recent
drone:{id}:telemetry
drone:{id}:commands

TTL Strategy:
• State: 5 seconds
• Alerts: 60 seconds
• Telemetry: 300 seconds

Performance:
• Read: 1-3ms
• Write: 1-2ms
• Throughput: 100K ops/sec

💾 PostgreSQL

Tables:
Drones - Master data
DroneEvents - All alerts
DroneTelemetry - Time-series
Missions - Flight plans

Indexes:
• DroneEvents: (DroneId, Timestamp)
• Telemetry: Clustered by time

Partitioning:
• Monthly partitions
• 3-month retention
• Archive to S3

🔍 Elasticsearch

Indices:
drone-events-YYYY.MM
drone-telemetry-YYYY.MM

Mapping:
• eventType: keyword
• message: text (analyzed)
• timestamp: date
• metadata: object

Use Cases:
• Full-text search
• Aggregations
• Analytics dashboards
• Log analysis
